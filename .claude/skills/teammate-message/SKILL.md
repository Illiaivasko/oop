name: teammate-message
description: Use BEFORE drafting ANY message a human will post to a teammate, manager or stakeholder - chat, tracker comment, email - a status, an estimate, a "done" reply to their asks, a question, a ping. Do not free-write it.
---
Adapted from: our PM-update skill + our lessons (a teammate called a batch of updates "so hard to read"; a "done" reply carried filler and an internal fix that changed nothing for the reader; a ping re-asked something already waiting in another thread).

**Core rule:** only what the reader acts on, in the sender's own voice, short and plain.

## Before drafting
- Read the thread / unit's CURRENT comments. If the ask already exists somewhere, nudge that thread - do not re-ask.
- Read 2-3 messages the sender actually posted to this reader; copy their shape.
- Read the LATEST messages in the exact place it will be posted (that DM / channel / thread / unit), including what the sender already sent and any reply after it. Answer what was said last; don't repeat or re-ask.
- Offered this draft earlier in the session? Re-read that conversation before offering it again - it may already be sent or answered.
- Who is in that place decides who you can address: never @-mention someone who isn't in it - write them a separate message.
- Before handing over, search each ask across all channels of the last few days. Already asked -> drop it, or nudge only if the sender wants one.

## Rules
- Match the language and register of THAT conversation: a casual chat in another language stays casual and in that language, a formal channel stays formal.
- First person as the sender ("I", "my"). "We" only when it truly means several humans. You are not a teammate.
- SHORT. One point per unit + the ask. No re-telling history, no headers or bold labels in a chat message.
- No internal jargon (layer names, "blast radius", "guard", "normalizer", function names). Say it plainly.
- Say WHERE it is ("on staging", "after the release") and what the reader can do now ("you can test").
- Estimates: plain, rounded to half-days / days, trivial ones grouped, blocked ones named with the time once unblocked.
- End with the one thing that matters (the priority or the ask), inside the same flow. A message that asks ends with ONE clear question.
- No asides in parentheses - make it its own short sentence or drop it.
- Questions to a group: one line per person, just the question, no background.
- Follow the team's mention and punctuation conventions exactly.

## Variants
| Situation | Shape |
|---|---|
| Status / estimate to a manager | one flowing paragraph |
| "Done" reply to a list of asks | answer THEIR points in THEIR order, one line each, their wording |
| A question | context in one sentence, the question, who decides |
| Daily / standup | what moved, what is left, blockers - no mechanics |

## Last step - humanize
Run `humanizer` in embedded mode on the final text, then check the rules above still hold (the sender's voice and format win over the humanizer).

## Red flags
Filler openers; an internal-only hardening reported to a reader it changes nothing for; a wall of text; "we" for the sender's own work; a message posted by the agent itself (draft only, the human sends).

## Example (reply to three asks)
> @<teammate> done, all 3:
> - the summary now includes the attendee list and the new total
> - sending the selected options recalculates and returns the updated summary
> - the skip text is the one from the design
> Updated doc attached. It's on staging, so you can test.
